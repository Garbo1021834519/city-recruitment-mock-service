# 城市招聘配置管理 1:1 行为还原设计

**日期：** 2026-10-21  
**目标站点：** `http://47.107.245.246:8080/cities`  
**目标：** 在本地构建一个可运行的城市招聘配置管理系统，使已观测的前端路由、页面行为、API 契约、认证、角色权限和数据操作与目标站点保持行为一致。

## 范围

还原所有已发现的角色和路由：`admin`、`customer`、`recruiter`，以及移动端入口 `/m`。当前前端包中已发现 38 条路由，包含登录、账号摘要、移动聊天、城市、工厂、服务岗位、节假日、城市关联、招聘员、设置、知识库、未知问题、用户、设备、会话、候选人、规则、评估、老客、状态看板、激活和招聘员精选模块。

目标是行为等价：页面结构、样式、路由跳转、表单字段、列表筛选、分页、状态变化、错误提示、文件导入导出和角色可见性按真实站点的可观测行为复现。目标站点没有提供后端源码和数据库，因此无法从网页证据证明的内部定时任务、隐藏校验或数据库实现会记录为未知，不把推测当作已还原事实。

## 总体架构

```text
原站 Vue 构建资源
        │
        │ 统一 API 基址
        ▼
本地静态资源服务 ── Fastify API ── JWT 认证/角色权限 ── SQLite
                                      │
                                      └─ 文件导入导出目录
```

### 前端

保留原站构建后的 JS、CSS、字体和图片资源，避免重写组件造成视觉和交互偏差。资源通过本地静态服务提供，API 地址通过兼容层配置或构建时替换指向本地 Fastify 服务。保留 38 条路由、路由守卫、懒加载模块和移动端入口；只在需要改变 API 地址时做最小变更。

### API

使用 Node.js 22、Fastify、`@fastify/static`、`@fastify/multipart`、`jsonwebtoken` 和 `node:sqlite`。API 路径保留 `/api/v1` 前缀。认证接口兼容：

- `POST /api/v1/auth/login`
- `GET /api/v1/auth/me`
- 401 时由前端清理登录状态并回到登录页

响应沿用目标站点已观测的 JSON 字段和错误字段 `detail`；每个接口保留分页、筛选、排序和状态字段的语义。

### 数据

SQLite 数据库位于本地项目的 `data/app.sqlite`，启动时执行迁移并插入可重复运行的种子数据。主表按已发现模块划分：

- `users`、`roles`、`user_roles`
- `cities`、`factories`、`service_positions`
- `holiday_schedules`、`city_links`
- `recruiters`、`settings`
- `knowledge_items`、`unknown_questions`
- `agent_devices`、`conversations`、`candidates`
- `agent_rules`、`agent_evaluations`、`old_friends`
- `status_records`、`activation_strategies`、`activation_devices`、`activation_scripts`

关系、枚举和字段以真实接口响应、前端表单和列表渲染代码为准；未知字段保留可扩展 JSON 列，直到运行证据足以确定结构。

### 认证和权限

本地 JWT 使用短期访问令牌；令牌只用于本地实验。登录成功返回 `access_token` 和 `token_type: bearer`，前端所需的 `username`、`role`、`recruiter_type`、`recruiter_id` 由 `/auth/me` 提供。权限中间件按角色和路由映射检查访问，未认证返回 401，无权限返回 403，并保持前端现有跳转逻辑。

## 功能恢复流程

### 阶段 1：资产和契约

从目标站点获取入口 HTML、主包、38 个懒加载 chunk、CSS 和公共资源；从静态代码提取路由、菜单、API 路径、HTTP 方法、参数名、请求体字段、上传字段和导出响应类型。输出：

- `过程文件/asset-manifest.json`
- `过程文件/route-manifest.json`
- `过程文件/api-contracts.json`
- `过程文件/unknowns.json`

### 阶段 2：核心运行链

先实现登录、当前用户、路由守卫、主布局、错误处理和公共分页/筛选组件，再实现城市、工厂、岗位三个核心模块。每个模块包括列表、详情、创建、编辑、删除、状态切换、复制和导入导出（页面存在时）。

### 阶段 3：管理模块

按路由表实现节假日、城市关联、招聘员、设置、知识库、未知问题、用户、设备、会话、候选人、规则、评估、老客、状态和激活模块。每个模块先以真实页面触发的请求为契约，再补齐页面中声明但当前账号未触发的分支。

### 阶段 4：移动端和角色

使用每个角色的账号或明确的权限响应验证菜单可见性、默认落点、路由拦截、移动聊天和招聘员专属页面。角色数据缺失时只验证静态代码中的守卫条件，并标记为待运行验证。

## 验证策略

每个模块都保存一个可复现的 REA 场景：登录、进入路由、执行一个只读操作、捕获 DOM/无障碍树/URL/网络元数据和必要的 JSON 形状。目标站点与本地站点使用相同步骤进行对比：

- 路由和重定向一致
- 页面标题、菜单、表单标签和按钮一致
- 请求方法、路径、查询参数和请求体字段一致
- 状态码、分页字段、列表字段和错误字段一致
- 操作后的 URL、提示、列表状态和存储状态一致

删除、上传、状态切换和批量导入先在本地数据库验证；对目标站点的写操作只在用户明确指定的测试数据上进行，并记录前后状态。验证输出放在 `过程文件/comparisons/`，不保存明文账号、密码、Cookie 或 JWT。

## 失败和边界处理

- 目标站点不可达：保留已经采集的资产和契约，暂停需要实时证据的模块。
- 接口返回未知字段：保留原始字段名和类型观察，使用兼容 JSON 存储，禁止静默丢弃。
- 角色权限证据不足：实现静态代码可证明的守卫，运行时状态标记为未知。
- 文件导入格式未知：先读取前端 `FormData` 字段和导出 MIME 类型，再生成最小样例验证。
- 目标站点数据变化：以同一会话中实时行为为准，资产哈希和采集时间写入清单。

- `npm run migrate` 初始化或升级 SQLite
- `npm run seed` 写入可重复的测试数据
- `npm run verify` 执行契约和关键页面验证
- 模块化 API、数据库迁移、种子数据和验证场景
- 路由、API、字段和未知项清单
- 不含凭据的行为差异报告

## 明确限制

这个项目会尽量做到浏览器可观察行为的 1:1 兼容。没有后端源代码、生产数据库、后台任务配置或所有角色的真实账号时，无法证明内部实现与目标站点相同；验收标准采用页面和接口行为一致，并对未观测部分明确标注证据等级。
